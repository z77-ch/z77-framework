## mental model

The system's language policy has a single source of truth: the dedicated
`config/i18n` config (ADR-013), carrying `defaultLanguage` (the one system-wide
fallback) and `languages` (the system-wide routing whitelist). The installer
generates `config/client/i18n.inc.php` from the `core-i18n` installer-config section
(defaults in `i18n.default.inc.php`), like `auth` / `moduleManager`. At runtime the
`I18n` service (DI key `I18n`, registered in `Bootstrap::pullUp()`) reads it;
consumers reach it via `DI::getI18n()`.

- `defaultLanguage` replaced the former scattered constants. "Set everything to `en`"
  = change this one key.
- **Resolution + persistence (revised 2026-06-08, ADR-015):** `Request::extractLanguage()`
  accepts a leading two-letter URL segment only if it is in `languages` (unknown →
  `InvalidRouteException`). **The rendered language of a resolved URL is determined by the
  URL alone** — a prefix sets it, its absence means `defaultLanguage`. The session NEVER
  overrides the rendered language of a resolved page (doing so made the prefix-less canonical
  `/home` render in whatever language the session held → unstable canonical / page-cache key).
  A valid prefix is the explicit choice and is persisted to the session; a prefix-less page
  view (GET/HEAD, Page mode, not a reserved route) forgets it again, because the default
  language has no prefix (I18N-SWITCH-DEFAULT-001) — the session holds the language of the
  last page viewed. The remembered
  preference is used **only to redirect the bare site root**: `/` + a non-default remembered
  language → 302 to `/{lang}`. `Request::applyLanguageSession(): ?string` returns that redirect
  target (else null); it runs in `Dispatcher::execute()` after `AccessGuard` started the session
  and before the page-cache decision, and the dispatcher issues the `RedirectResponse`.
- **Per-module switch (opt-in):** the global `languages` is the routing whitelist;
  a module's `languages` key (`App/Config/{module}Config.inc.php`, read via
  `ModuleManager::getModuleLanguages()`) is the switch offering for that environment.
  Omitted → no switch (admin backend stays single-language). The frontend declares
  `['de','fr']`. `AbstractBaseController::html()` builds `$languageSwitch` (filtered
  to the global whitelist; only when > 1 language) and injects it into every template;
  `partials/header.tpl.php` renders it in the topbar (`fe-topbar__nav--lang` /
  `fe-topbar__link--lang` — a compact uppercase group with a left divider) and in the
  mobile overlay (`fe-nav-overlay__list--lang`, a divided horizontal row). Styles live
  in the frontend SCSS (`_topbar.scss` / `_nav-overlay.scss` → `base.css`).
- **Switch link shape:** each entry is the current page's **canonical** form, passed through
  `localizedUrl()` for the target code — `AbstractBaseController::currentCanonicalPath()` (the
  canonical NavigationAlias path of `$current` + content slugs, ADR-015). NOT the as-requested
  path — a non-canonical alias still switches to the canonical localized URL. **The default
  language is NOT prefixed** (corrected 2026-09-17; the earlier "always prefixed, incl. the
  default" never matched `localizedUrl()`, which returns the prefix-less canonical URL for the
  default language): switching to `de` emits `/home`, switching to `fr` emits `/fr/accueil`.
  Since the alias-first amendment (2026-09-17) `localizedUrl()` localizes the ALIAS PART only —
  on a page without an alias (a convention route) the switch link is the same technical path
  with the language prefix, and in the default language the unchanged path.
- **Content language fallback:** `ContentService::find()` falls back to the
  `defaultLanguage` document when the requested-language document does not exist; an
  existing-but-inactive document does NOT fall back.
- The generated `skeleton/config/i18n.inc.php` and `skeleton/data/content/*.fr.json`
  are RUNTIME and ephemeral — regenerated/seeded by the installer from the SOURCE
  defaults; do not hand-edit.

## rules

- When needing the system default language in PHP → MUST read `DI::getI18n()->getDefaultLanguage()`; MUST NOT hardcode `'de'` or introduce a local `DEFAULT_LANGUAGE` constant.
- When accepting a language code from the URL or a request → MUST validate it with `I18n::isValidLanguage()`; MUST NOT accept an arbitrary two-letter segment.
- When changing the system default language ("set all to X") → MUST change `defaultLanguage` in the `config/i18n` source only; MUST NOT edit it in a module config or in code.
- When adding a globally servable language → MUST add it to `config/i18n.languages` via the installer-config source (`core-i18n`); MUST NOT hand-edit the generated `skeleton/config/i18n.inc.php`.
- When an environment should offer a language switch → MUST declare `languages` (a subset of the global whitelist) in its own `App/Config/{module}Config.inc.php`; omitting the key MUST mean no switch (opt-in); MUST NOT rely on inheriting the global set.
- When building a language-switch link in a template → MUST use the injected `$languageSwitch` items (`code`/`url`/`active`); MUST NOT construct language URLs ad-hoc in the template.
- When loading frontend content in a language → MUST go through `ContentService::find()`/`render()` so the default-language fallback applies; MUST NOT read the repository per-language directly on the frontend.

## known issues

- **I18N-SWITCH-DEFAULT-001** — resolved 2026-09-17. The switch to the default language was
  never remembered: the default-language entry is a prefix-less URL (`/home`) and only a URL
  PREFIX wrote the session, so `fr → de` rendered German but kept `fr`, and the next visit to
  the bare root `/` (the logo link) redirected back to `/fr`. Fix in
  `Request::applyLanguageSession()`: a prefix-less PAGE view — GET/HEAD, Page mode, not a
  reserved route — removes the remembered language. What is remembered is therefore the
  language of the last page viewed. Deliberately NOT resetting: Fetch calls (a form's blur
  check posts prefix-less from a French page — TRANS-CHECK-URL-001), POSTs, and reserved
  routes (a `/media` file opened in a new tab). Prefixing the default language in the switch
  was rejected (a second URL per page, I18N-LANG-STABLE-001). Verified:
  `tests/language-session.php` (click path `/fr` → `/home` → `/` stays German, the
  non-resetting cases, root edge cases) and end to end on zihlundsee.ch.

- Don't assume the page cache is shared across languages: the page cache keys per language (`PageIdentity` includes `language`). A visitor gets a session only to remember a switch preference for the root redirect (below) — the rendered language itself is URL-derived.

- **I18N-LANG-STABLE-001** — resolved 2026-06-08 (ADR-015, Variante B). The prefix-less canonical URL was not language-stable: `applyLanguageSession()` adopted the session language for any prefix-less request, so `/home` rendered de or fr depending on the session (broken canonical + wrong-language page-cache entry under the de key). Fix: a prefix-less resolved URL ALWAYS renders `defaultLanguage`; the session only redirects the bare root `/` → `/{lang}`. `applyLanguageSession()` now returns the optional redirect target; `Dispatcher` issues it. Supersedes ADR-013 §"Language resolution & persistence" (the "prefix-less adopts remembered language" clause). Verified: fr-session + `/home` → `<html lang="de">`; fr-session + `/` → 302 `/fr`.

- **Per-module subset validation** — resolved 2026-06-07. `getModuleLanguages()` now fails fast: a module that declares a non-empty `languages` set MUST include the system `defaultLanguage` (the guaranteed fallback). Omitting it throws a `RuntimeException` at the consumption boundary instead of silently relying on the implicit fallback. An empty/absent declaration still means "no switch" (opt-out), no assertion.
